**\# Docent Implementation Specification**

**\#\# 0\. 문서의 목적**

**본 문서는 웹전시의 과학해설사(Docent) 시스템을 구현하기 위한 명세이다.**

**이 문서는 콘텐츠를 생성하기 위한 프롬프트가 아니다.**

**과학해설사의 대사, 질문, 선택지, Scene 및 콘텐츠는 구현 전에 확정된 \`dialogue.md\`를 원본(Source of Truth)으로 사용한다.**

**구현 과정에서 AI는 새로운 대사, 선택지, 과학적 설명, 출처, Scene, 화면 연출 또는 콘텐츠를 임의로 생성하거나 보완하지 않는다.**

**문서에 명시되지 않은 사항은 추론하여 확정하지 않는다.**

**\---**

**\# 1\. 시스템 역할**

**\#\# 1.1 과학해설사의 성격**

**과학해설사는 일반적인 대화형 챗봇이 아니다.**

**방문자가 미리 정의된 질문을 선택하고, 그에 대응하는 확정된 대화문을 따라 진행하는 비주얼 노벨형 인터랙티브 해설 시스템이다.**

**기본적인 흐름은 다음과 같다.**

**START**  
**→ 질문 선택**  
**→ 해당 질문의 대화**  
**→ RETURN**  
**→ 다른 질문 선택 또는 END**

**방문자가 자유롭게 문장을 입력하여 새로운 답변을 생성하는 기능은 구현하지 않는다.**

**\#\# 1.2 해설사의 역할**

**과학해설사는 현재 전시 화면 위에서 작동한다.**

**해설사 호출 시 별도의 페이지로 이동하거나 현재 전시 화면을 대체하지 않는다.**

**해설사 UI는 현재 전시물과 함께 표시되어야 하며, 전시물의 관람을 방해하지 않도록 설계한다.**

**\---**

**\# 2\. Source of Truth**

**과학해설사 구현에서 다음 문서의 역할을 구분한다.**

**\- \`main.md\`**  
  **\- 전체 전시의 구조, 동선, 디자인 및 기능에 대한 상위 기획 기준**

**\- \`con\_Mapping.md\`**  
  **\- 전시 화면과 동물, 패널, 에셋, 퀴즈 및 해설사의 연결 관계**

**\- \`dialogue.md\`**  
  **\- 과학해설사의 실제 대사, 질문, 선택지, Scene 및 진행 구조에 대한 원본(Source of Truth)**

**\- \`docent.md\`**  
  **\- 과학해설사 UI와 실행 방식에 대한 구현 명세**

**\- \`references.md\`**  
  **\- 과학 자료 및 이미지·3D·영상 에셋의 출처 코드 관리**

**각 문서는 담당 범위에서 Source of Truth로 간주한다.**

**특정 문서의 담당 범위에 관한 정보가 다른 문서와 다를 경우 임의로 내용을 생성하거나 수정하지 않는다.**

**\---**

**\# 3\. Dialogue 데이터 규칙**

**\#\# 3.1 확정 콘텐츠의 직접 실행**

**\`dialogue.md\`의 대사와 선택지는 수정 없이 실행한다.**

**다음 항목을 임의로 변경하지 않는다.**

**\- 대사**  
**\- 질문 문구**  
**\- 선택지 문구**  
**\- 선택지의 수**  
**\- Scene의 순서**  
**\- RETURN 연결**  
**\- END 연결**  
**\- 화자**  
**\- 표정 및 상태값**

**\#\# 3.2 선택지**

**선택지의 수는 \`dialogue.md\`에 정의된 값을 그대로 사용한다.**

**특정한 고정 개수의 선택지를 강제하지 않는다.**

**\`dialogue.md\`에 3개의 선택지가 있으면 3개를 표시하고,**  
**4개가 있으면 4개를 표시하며,**  
**5개가 있으면 5개를 표시한다.**

**선택지를 추가하거나 삭제하지 않는다.**

**\#\# 3.3 대화 진행**

**각 대화는 \`dialogue.md\`에 정의된 구조에 따라 진행한다.**

**기본적인 구조는 다음과 같다.**

**START**  
**→ 질문 선택**  
**→ Q**  
**→ RETURN**  
**→ 질문 선택 또는 END**

**구현자는 대화 흐름을 임의로 변경하지 않는다.**

**\`dialogue.md\`에 존재하지 않는 Scene이나 질문을 새로 생성하지 않는다.**

**\#\# 3.4 대화 내용의 생성 금지**

**다음과 같은 행위를 하지 않는다.**

**\- 과학 패널을 바탕으로 새로운 대사를 작성**  
**\- 기존 대사를 더 자연스럽게 수정**  
**\- 부족해 보이는 설명을 추가**  
**\- 질문이 부족하다고 판단하여 질문 추가**  
**\- 선택지가 부족하다고 판단하여 선택지 추가**  
**\- 누락된 Scene 생성**  
**\- 대화의 과학적 내용을 임의로 보완**  
**\- 기존 대사를 요약하거나 재작성**

**콘텐츠가 누락되어 있는 경우 누락된 상태를 유지한다.**

**\---**

**\# 4\. 해설사 UI**

**\#\# 4.1 기본 UI**

**해설사는 현재 전시 화면 위에 오버레이 형태로 표시한다.**

**해설사 UI는 다음 요소를 포함할 수 있다.**

**\- 해설사 캐릭터**  
**\- 캐릭터 표정**  
**\- 대화창**  
**\- 화자명**  
**\- 대사**  
**\- 질문 선택지**  
**\- 진행 및 닫기 UI**

**구체적인 UI 구성은 프로젝트의 전체 디자인 명세를 따른다.**

**\#\# 4.2 전시물과의 관계**

**해설사 UI는 전시물의 정보를 가리거나 관람을 방해해서는 안 된다.**

**해설사를 호출해도 현재 전시 화면과 전시물의 맥락은 유지한다.**

**해설사는 전시 화면을 별도의 해설사 전용 페이지로 교체하지 않는다.**

**\---**

**\# 5\. 캐릭터 상태**

**\`dialogue.md\`에 표정 또는 상태값이 지정되어 있는 경우 해당 값을 사용한다.**

**예:**

**\- \`neutral\`**  
**\- \`explaining\`**  
**\- \`enlightened\`**  
**\- \`surprised\`**  
**\- \`excited\`**  
**\- \`thinking\`**

**상태값을 임의로 변경하거나 새로운 상태를 생성하지 않는다.**

**대사 내용만을 근거로 새로운 표정이나 상태를 추론하여 추가하지 않는다.**

**\---**

**\# 6\. Exhibition Interaction**

**\#\# 6.1 기본 원칙**

**해설사와 전시물의 연동은 \`dialogue.md\` 또는 다른 확정된 구현 명세에 명시된 경우에만 실행한다.**

**해설사 대사를 근거로 구현자가 임의의 전시물 인터랙션을 생성해서는 안 된다.**

**\#\# 6.2 화면 연출**

**다음과 같은 연출은 명시된 경우에만 실행한다.**

**\- 카메라 이동**  
**\- 카메라 확대 및 축소**  
**\- 3D 모델 회전**  
**\- 특정 부위 하이라이트**  
**\- 특정 오브젝트 강조**  
**\- 패널 강조**  
**\- 관련 이미지 표시**  
**\- 전시물 상태 변경**  
**\- 기타 화면 전환 및 효과**

**\#\# 6.3 연출 데이터가 없는 경우**

**\`dialogue.md\`에 특정 화면 연출이 명시되어 있지 않은 경우 임의로 연출을 생성하지 않는다.**

**예를 들어 다음과 같은 판단을 구현자가 임의로 하지 않는다.**

**\- 특정 대사가 발에 관한 내용이므로 발을 확대**  
**\- 동물의 특정 부위를 설명하므로 해당 부위를 하이라이트**  
**\- 대사의 감정에 맞추어 카메라를 이동**  
**\- 과학적 설명에 어울린다고 판단하여 애니메이션 추가**

**명시된 연출이 없는 경우 시스템의 기본 동작을 사용한다.**

**\---**

**\# 7\. 기본 동작과 콘텐츠 판단의 구분**

**문서에 콘텐츠가 명시되지 않은 경우에도 시스템의 일반적인 UI 동작은 사용할 수 있다.**

**예:**

**\- 대화창 표시**  
**\- 대사 진행**  
**\- 선택지 표시**  
**\- 선택지 클릭**  
**\- RETURN 처리**  
**\- END 처리**  
**\- 해설사 UI 열기 및 닫기**

**그러나 다음과 같은 콘텐츠적 판단은 기본값으로 추론하지 않는다.**

**\- 새로운 대사**  
**\- 새로운 질문**  
**\- 새로운 선택지**  
**\- 새로운 과학적 설명**  
**\- 새로운 출처**  
**\- 새로운 Scene**  
**\- 새로운 화면 연출**  
**\- 새로운 전시물 인터랙션**

**\---**

**\# 8\. Missing Content Policy**

**\#\# 8.1 누락 콘텐츠**

**다음 항목이 \`dialogue.md\`에 존재하지 않는 경우 임의로 생성하지 않는다.**

**\- 대사**  
**\- 질문**  
**\- 선택지**  
**\- Scene**  
**\- 과학적 설명**  
**\- 캐릭터 상태**  
**\- 화면 연출**  
**\- 전시물 연동 정보**

**\#\# 8.2 누락된 연출**

**화면 연출 정보가 없는 경우 임의의 카메라 이동, 확대, 하이라이트 또는 애니메이션을 추가하지 않는다.**

**시스템의 기본 동작으로 처리할 수 있는 경우 기본 동작을 사용한다.**

**구현상 판단이 필요한 경우 사용자 확인이 필요하다.**

**\#\# 8.3 누락된 출처**

**출처 정보가 없는 경우 새로운 출처를 검색하거나 추정하여 추가하지 않는다.**

**\`references.md\`에 존재하지 않는 R/A 코드를 임의로 생성하지 않는다.**

**\---**

**\# 9\. 과학적 콘텐츠 보호**

**과학해설사의 대화는 이미 검토 및 확정된 콘텐츠이다.**

**따라서 구현자는 과학적 정확성을 이유로 대사를 임의 수정하지 않는다.**

**다음 행위를 금지한다.**

**\- 과학적 설명의 임의 수정**  
**\- 전문용어의 임의 변경**  
**\- 과학적 사실의 추가**  
**\- 과학적 사실의 삭제**  
**\- 기존 대사의 의미를 유지한다는 이유로 한 문장으로 재작성**  
**\- 과학 패널의 내용을 이용한 새로운 대화 생성**

**\---**

**\# 10\. 출처 및 에셋 연결**

**출처 및 에셋은 \`con\_Mapping.md\`와 \`references.md\`에 명시된 연결 관계를 따른다.**

**콘텐츠에 \`\[R\#\#\]\` 또는 \`\[A\#\#\]\` 코드가 연결되어 있는 경우 해당 코드를 사용하여 출처 및 에셋을 추적한다.**

**코드가 연결되어 있지 않은 콘텐츠에 대해 구현자가 임의로 R/A 코드를 생성하거나 기존 자료와 연결하지 않는다.**

**출처가 확인되지 않은 경우 출처를 추정하거나 새로 생성하지 않는다.**

**\---**

**\# 11\. 동물 및 전시물 연결**

**동물 및 전시물의 식별자는 \`con\_Mapping.md\`의 매핑을 따른다.**

**\`dialogue.md\`와 연결할 때 동물명 또는 코드가 일치하는지 확인한다.**

**코드 또는 연결 관계가 불명확한 경우 임의로 추론하지 않는다.**

**잘못된 대화가 호출될 가능성이 있는 경우 구현을 진행하기 전에 확인한다.**

**\---**

**\# 12\. 구현 검증**

**구현 전 다음 사항을 확인한다.**

**\#\#\# Dialogue**

**\- \`dialogue.md\`의 모든 필요한 Scene이 로드되는가?**  
**\- START가 정상적으로 시작되는가?**  
**\- 질문 선택지가 정확히 표시되는가?**  
**\- 선택지의 문구가 원문과 일치하는가?**  
**\- 선택지의 수가 원문과 일치하는가?**  
**\- RETURN이 올바른 위치로 연결되는가?**  
**\- END가 정상적으로 종료되는가?**

**\#\#\# Character**

**\- 지정된 표정 및 상태값이 정상적으로 표시되는가?**  
**\- 존재하지 않는 상태값을 임의로 생성하지 않았는가?**

**\#\#\# Exhibition**

**\- 해설사가 현재 전시 화면 위에서 작동하는가?**  
**\- 해설사 호출이 전시 화면을 대체하지 않는가?**  
**\- 명시된 연출만 실행되는가?**  
**\- 명시되지 않은 연출을 임의로 추가하지 않았는가?**

**\#\#\# Content Integrity**

**\- 대사가 변경되지 않았는가?**  
**\- 질문이 변경되지 않았는가?**  
**\- 선택지가 변경되지 않았는가?**  
**\- Scene이 추가 또는 삭제되지 않았는가?**  
**\- 과학적 설명이 추가되지 않았는가?**  
**\- 출처가 임의로 생성되지 않았는가?**

**\---**

**\# 13\. 구현 원칙**

**본 시스템의 구현자는 다음 원칙을 최우선으로 한다.**

**1\. 확정된 콘텐츠를 그대로 실행한다.**  
**2\. 콘텐츠를 임의로 생성하지 않는다.**  
**3\. 콘텐츠를 임의로 수정하지 않는다.**  
**4\. 누락된 콘텐츠를 추론하여 보완하지 않는다.**  
**5\. 명시된 연출만 실행한다.**  
**6\. 명시되지 않은 연출은 임의로 생성하지 않는다.**  
**7\. 출처와 에셋 정보를 추정하지 않는다.**  
**8\. 문서 간 충돌이 발생하면 임의로 하나를 선택하지 않는다.**  
**9\. 구현에 필요한 정보가 부족한 경우 사용자에게 확인한다.**  
**10\. 구현의 편의를 위해 콘텐츠 원본을 변경하지 않는다.**

**\---**

**\# 14\. 구현 절차**

**구현은 다음 순서로 진행한다.**

**1\. 기존 프로젝트 구조를 확인한다.**  
**2\. \`main.md\`를 확인하여 전체 전시 구조와 동선을 파악한다.**  
**3\. \`con\_Mapping.md\`를 확인하여 전시물·동물·에셋·해설사 연결 관계를 파악한다.**  
**4\. \`dialogue.md\`를 읽어 실제 해설사 콘텐츠 구조를 파악한다.**  
**5\. \`references.md\`를 확인하여 출처 및 에셋 연결 관계를 확인한다.**  
**6\. 기존 구현에서 사용할 수 있는 시스템과 컴포넌트를 우선 확인한다.**  
**7\. 필요한 경우 한 개의 해설사 패널을 먼저 구현하여 동작을 검증한다.**  
**8\. 검증된 구현을 다른 해설사 콘텐츠에 확장한다.**  
**9\. 모든 대화의 흐름과 콘텐츠 무결성을 검증한다.**

**구현 과정에서 문서에 없는 콘텐츠를 생성하여 빈 부분을 채우지 않는다.**

**\---**

**\# 15\. 최종 원칙**

**이 프로젝트에서 AI의 역할은 과학해설사 콘텐츠를 새롭게 창작하는 것이 아니다.**

**이미 작성되고 검토된 콘텐츠를 정확하게 웹전시의 인터랙션으로 구현하는 것이다.**

**따라서 다음 원칙을 최우선으로 한다.**

**\> \*\*Create nothing. Assume nothing. Change nothing.\*\***  
**\>**  
**\> \*\*확정된 콘텐츠를 그대로 구현한다.\*\***
